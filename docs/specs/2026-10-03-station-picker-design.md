# 역 선택 오류 수정·검색·즐겨찾기

## 원인과 요구사항
현재 서버는 역 이름이 목록에 있는지만 확인하고 화면은 같은 전체 목록을 양쪽 select에 넣는다. 따라서 수원→동탄처럼 직통 고속열차가 없는 구간도 선택된다.

1. 출발역에서 직통으로 갈 수 있는 역만 도착 목록에 제공한다. 즐겨찾기·검색·역 바꾸기에서도 같은 제한을 적용한다.
2. 출발·도착 선택은 검색 입력이 포함된 드롭다운으로 제공한다. 클릭, 방향키, Enter, Escape, Tab을 지원한다.
3. 별표로 즐겨찾기 역을 추가·해제하고 목록 상단에서 빠르게 선택한다. 이 브라우저에 저장하며 새로고침 후 유지한다. 운행하지 않는 즐겨찾기는 도착 후보로 우회 노출하지 않는다.

## 구현 기준
공식 코레일 시간표의 개별 열차 정차역 조합으로 직통 도착 후보를 만든다. 같은 노선 태그나 환승 경로의 연결만으로 직통이라고 추론하지 않는다. 날짜별 운휴·잔여석은 실제 조회로 확인하며 시간표 기준일과 출처를 기록한다. 구형 SRT 연결도 별도 정차 패턴을 적용한다.

서버가 역·도착 가능 목록을 소유하고 프론트는 API 자료로 선택기를 구성한다. 기존 저장 설정 읽기는 보존하되 불가능한 구간의 저장·시작은 입력 오류로 거부한다. 출발역 변경으로 기존 도착역이 불가능해지면 선택을 비우고 다시 선택하도록 안내한다. 임의 도착역을 대신 저장하지 않는다.

기존 네이비·청록 디자인을 유지하며 역 선택 UI만 확장한다. 즐겨찾기는 공개 계정 설정과 분리된 localStorage를 사용하며 저장 불가·잘못된 데이터에도 화면이 동작하도록 한다.

## 검증
서버 회귀 테스트: 수원→동탄/수서 제외, 수원→부산/서울 포함, 분기 간 불가능 구간, 반대 방향, 동일역 제외, API 저장·시작 검증, 기존 설정 보존.
브라우저: 검색 선택, 출발 변경 시 도착 초기화, 검색 결과 없음, 즐겨찾기 추가·해제·재접속 유지, 즐겨찾기 경로 제한, 키보드, 모바일, 실행 중 잠금.
기존 순차 서브에이전트 선호에 따라 서버 구현→화면 구현→독립 검토 순서로 수행한다. 실제 계정 로그인·예약·알림은 실행하지 않는다.
