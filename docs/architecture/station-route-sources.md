# 직통 역 목록의 근거와 갱신

`backend/data/station_routes.json`은 한국철도공사 공식 **KTX 시간표(2026. 10. 1. 기준)**의 개별 열차 정차 순서를 저장한 스냅샷이다. 2026-10-03 확인했으며, 운행요일이 다른 열차도 포함한다. 특정 날짜·시간의 운행 여부와 잔여석은 실제 열차 조회에서 확인한다.

- 공식 게시판: <https://www.korail.com/com/userBoard.do?mode=list&schBcid=ticketTable> (`bdIdx=26041`)
- 첨부파일: <https://www.korail.com/file/cubedata/COMMON/jfile/202609/23/202609231a0cb38a2c5200.xlsx>
- 다운로드 경로는 공식 홈페이지의 공개 JavaScript에 있는 `/file/cubedata/COMMON/` + `fileId` 링크에서 확인했다.
- 파일 SHA-256, 기준일, 9개 시트 이름, 621개 열차행 수는 JSON의 `source`에 기록했다. 각 열차에는 원본 시트·행 번호·열차번호·편성·요일·정차역을 보존했다.

## 생성 방식

각 시트의 `열차번호`, `편성`, `비고` 머리글로 상행·하행 표를 **분리**한다. KTX 계열 열차행의 역 칸 중 실제 시간이 있는 칸만 읽는다. 이 파일에서는 수치 0(표시상 빈칸)이 무정차이며, 0보다 큰 Excel 시간 값은 정차다. 1 이상인 다음날 시간도 포함한다. 수식은 실행하지 않고 공식 파일의 저장된 결과만 읽는다. 운행요일과 주석은 역으로 읽지 않는다. 알려지지 않은 편성/표 구조는 실패시켜 잘못된 목록으로 갱신하지 않는다.

같은 열차행에서 앞에 있는 정차역→뒤에 있는 정차역만 허용한다. 다른 열차의 역을 합치거나, 환승 가능한 연결을 직통으로 보거나, 역순 운행을 자동으로 만들지 않는다. 병결 열차도 각 열차행을 독립적으로 처리하므로 다른 종착지의 정차역을 연결하지 않는다. 역 이름은 앱의 별칭 규칙으로 통일한다(김천구미→김천(구미), 울산→울산(통도사), 판교(경기)→판교, 여수엑스포→여수EXPO 등).

구형 `legacy_srt`는 별도 역사 시간표를 추정하지 않는다. **같은 공식 시간표에서 수서 출발 또는 도착 열차행만 골라** 기존 SRT 역 코드 지원 목록 안의 역 쌍으로 제한한다. 최신 시간표는 해당 열차도 KTX 계열로 표시한다. 이 목록은 구형 연결의 호환 범위이며, 구형 SRT 서비스의 운영이나 예약 가능성을 보장하지 않는다. 이 한계는 API `source.legacy_srt_scope`에도 표시한다.

## 재생성

외부 라이브러리가 필요 없는 표준 Python 도구다. 프로젝트 폴더에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -m tools.update_station_routes --input tools/source/korail-2026-10-01.xlsx
```

`--input`을 생략하면 위 공식 첨부파일을 공개 GET으로 받아 생성한다. 최신 시간표로 교체할 때는 공식 게시판에서 파일과 기준일을 확인하고 도구의 `DOWNLOAD_URL`, 출처 메타데이터를 함께 갱신한다. 새 정차역이 있으면 `backend/stations.py`의 역 목록과 별칭도 갱신한다. 코드가 확인되지 않은 코레일 역은 `None`을 유지한다. 런타임은 인터넷 다운로드 없이 검토된 로컬 스냅샷을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_station_routes.py -q -p no:cacheprovider
```

## API 계약

`GET /api/station-routes`는 `{stations, destinations: {korail, legacy_srt}, source}`를 반환한다. `stations`는 기존 `/api/stations`와 같으며 각 항목의 `aliases` 배열로 검색 별칭을 제공한다. `destinations[mode][출발역]`은 허용되는 도착역 이름 배열이다. 해당 연결에서 출발 불가능한 역은 빈 배열이다. 자기 자신은 포함하지 않는다.

기존 설정은 읽을 수 있다. 공개 설정 저장은 **저장된 값과 요청의 부분 변경을 합친 뒤** 직통 여부를 확인하고 실패하면 422, 시작은 400을 반환한다. 잘못된 구간은 저장하거나 감시를 시작하기 전에 거부한다. 프론트는 기존 잘못된 구간을 자동 대체하지 않고 재선택을 안내한다.

두 POST 요청에는 요청 전용 `PublicConfigUpdate` 모델을 사용한다. 개별 필드의 형식·범위·별칭 검증은 유지하되 역 쌍, 총인원, 좌석종류, 시작·종료 시간의 관계 검증은 저장값을 병합한 `MonitorConfig`에서 수행한다. 요청에 생략된 값을 기본값과 비교하여 정상적인 부분 변경을 거부하지 않도록 한다. 완전한 `PublicConfig`와 `MonitorConfig`의 관계 검증은 그대로 유지한다.

요청에 `schema_version`이 없으면 현재 형식의 부분 변경으로 처리한다. 따라서 `poll_interval`만 바꿀 때 기존 `legacy_srt` 연결이나 이전 안내를 덮어쓰지 않는다. 요청이 명시한 v1 형식과 저장된 구형 파일의 이전 처리는 유지한다.
