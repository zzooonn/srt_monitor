# Rail Monitor 구현 검증 기록

검증일: 2026-10-03. 서버, 화면, 실행 안내를 순차 서브에이전트로 구현하고 각 단계의 요구사항·품질 검토를 완료했다. 최종 통합 검토에도 중요한 미해결 지적이 없다.

## 브라우저 검증

별도 임시 설정 파일과 모의 코레일·SRT 연결을 사용했다. 철도사 예약 호출은 실행되지 않도록 차단하고 텔레그램 전송도 비활성화했다.

- 초기 설정 로드, 계정 미설정 안내, 단일 여정·승객 유형 저장과 저장값 복원.
- 성공한 계정 저장 후 입력란 비우기, 모의 조회 시작·중지, 최근 조회·실행 연결 표시.
- 실행 중 설정 편집 잠금, 실제 이벤트 목록과 SSE 연결 상태 구분, 이벤트 중복 제거.
- 조회·생존 알림 주기 보존, 장애인 운임 자동 예약 제한 및 알림 전용 모드 저장.
- 불확실 예약 상태의 중지 후 유지·재시작 차단, 예약 없음 확인으로 해제, 예약 있음 확인으로 예약 수와 목표 상태 반영.
- 코레일+와 이전 SRT 연결별 예약 확인 안내.
- 모바일 폭 375px에서 가로 넘침 없이 여정 바꾸기·저장·시작·중지.
- 초기 설정 조회 실패 시 저장·시작 차단 및 복구. 상태 조회 실패 시 마지막 응답 표시·작업 차단 및 복구.
- 낮은 데스크톱 화면에서도 정상 스크롤로 시작·중지 버튼 접근.

## 실행 및 남은 외부 확인

실행 주소는 `http://127.0.0.1:8000/`이며 최종 확인 시 실제 앱은 대기 상태다. 임시 검증 서버는 종료했다. 이후 실행 방법은 `WEB_README.md`와 `run_web.bat`을 따른다.

실계정 로그인, 실제 통합 구간 조회·예약·취소, 실제 텔레그램 전달은 검증하지 않았다. 모의 테스트 통과는 실제 철도사 API 성공을 보장하지 않는다. 필수 좌석 위치를 응답에서 확인할 수 없으면 예약을 유지하고 공식 앱에서 직접 확인해야 한다. 예약 잠금·수는 서버 프로세스 메모리에 있으므로 서버 재시작 전 기존 예약을 확인해야 한다.
