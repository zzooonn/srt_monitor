2026-10-03, 프로젝트 Python 3.12 가상환경 및 Node.js로 검증했다. 서버 구현 → 명세 검토 → 품질 검토 → 화면 구현 → 명세 검토 → 품질 검토 순서로 개별 서브에이전트를 사용했다. 검토에서 발견한 부분 요청 병합, 생략된 연결 방식 보존, 별표 포인터·키보드 초점 문제를 수정하고 재검토를 통과했다.

## 자동 검증

`.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider`: **273 passed**, 스킵 없음. 서버 269개와 프론트 규칙·초점 4개가 포함된다. Starlette/httpx 의존성의 사용 중단 예고 1건이 있다.

`api.js`, `app.js`, `station-model.js`, `station-picker.js`: Node.js `--input-type=module --check`에 각 파일을 표준 입력으로 전달하여 문법 검사 통과.

공식 2026-10-01 시간표의 9시트·621개 열차행·88역을 사용한다. 스냅샷 재생성 결과와 원본 SHA-256이 일치하며, 독립 openpyxl 재해석에서도 모든 정차 순서가 일치했다. 출처·범위·재생성 방법은 [직통 역 목록의 근거](../station-route-sources.md)에 기록한다. 코레일 1,807개와 이전 SRT 호환 범위 505개의 방향별 역 쌍이며, 노선 태그·환승·역순 추론은 하지 않는다.

## 실제 브라우저 확인

프로젝트의 실제 FastAPI 앱에 임시 설정과 모의 철도사 응답을 연결해 `127.0.0.1:8765`에서 확인했다. 실제 계정 로그인·열차 조회·예약·취소·텔레그램 전송은 하지 않았다.

- 저장된 수원→동탄 설정을 읽어 화면을 열고, 출발 수원 유지·도착 비움·재선택 안내·미저장 표시 확인.
- 수원 도착 후보는 대전·김천(구미)·동대구·경주·울산(통도사)·부산·서울·영등포이며 동탄·수서는 제외. 동탄 검색 결과 없음.
- 신경주 별칭 검색 → 경주 결과 → 방향키·Enter 선택.
- 부산 즐겨찾기 등록·상단 그룹·새로고침 유지·선택·여정 저장 확인. Tab으로 별표 이동·Enter 해제·재렌더 초점 유지·Escape 복귀·새로고침 후 해제 유지 확인.
- 출발 목록의 동탄을 즐겨찾기로 등록해도 수원 출발 도착 목록과 검색에서는 제외.
- 서울→강릉 선택 후 출발을 수원으로 변경하면 도착 선택을 비우고 안내. 도착 미선택 저장 시 실제 도착 검색 필드에 오류와 초점 표시.
- 동탄→서대전의 역 바꾸기는 반대 방향 직통이 없으므로 기존값 유지·안내. 이전 SRT 연결 변경 시 도착 재선택 및 수원 출발 검색 제외.
- 저장값 복원 시 선택기·요약·연결 방식 동기화.
- 알림 전용 모의 감시 시작 시 검색·목록·별표 잠금 및 팝업 닫힘. 중지 후 편집 가능.
- 역 구간 API를 검증용 503으로 실패시키면 초기 로드·저장·시작 차단. 실패 해제 후 상태 새로고침으로 정상 복구.
- 모바일 390px 브라우저 크기(문서 가용 폭 375px), 도착 팝업 좌우 51~341px·폭 290px, 문서 수평 넘침 없음. 목록 내부 스크롤과 표시 확인 후 브라우저 크기 복원.

스크린샷은 `images/station-picker-desktop.png`와 `images/station-picker-mobile.png`에 저장했다. 실제 `127.0.0.1:8000` 서버는 실행·예약 수·불확실 잠금이 없음을 확인한 뒤 수정본으로 재시작하고, 역 구간 API 200 및 실제 화면 로드를 확인했다. 실제 사용자 설정이나 계정은 검증 과정에서 저장하지 않았다.
